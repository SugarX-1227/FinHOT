# FinHOT 产品规划与开发路线（讨论稿 v0.1）

> 写于 2026-10-10。参考：AIHOT 开源仓库（引擎、提示词、文档、页面截图）、FinHOT 现状。
> aihot.news 线上站对机房 IP 有拦截，未能直接抓取；但仓库与线上跑的是同一份引擎，功能以仓库为准。
> 本文是讨论稿，第 10 节列出了需要拍板的问题。

---

## 0. 一句话结论

**不要做"A股版 AIHOT"，要做"新闻驱动的 A 股题材雷达"。**

AIHOT 的强项是"把一个行业的资讯流变成可读、可信、可订阅的精选与事件"。这套方法（事件聚簇、热度、精选门槛、校准、多出口）我们应该照搬。

但金融资讯有一个 AI 资讯没有的东西：**每条新闻都可以被市场验证**。新闻 → 题材 → 板块/个股 → 资金和涨跌，这条链是 FinHOT 已经开始做、别人很少系统做的。对外发布的真正价值也在这里：

- 告诉读者今天什么事重要（AIHOT 已经做到的）；
- 再告诉他市场认不认、过去这类信号靠不靠谱（只有金融能做，也是我们的护城河）。

## 1. 现状盘点：FinHOT vs AIHOT

| 能力 | AIHOT | FinHOT 现状 | 差距 |
|---|---|---|---|
| 采集频率 | 持续运行，活跃源最快 15 分钟一次 | 每天 2 次批处理（GitHub Actions） | **大**：盘中无法使用 |
| 信源类型 | RSS / 网页列表 / JSON / X / 公众号 / 外部推送；三级信源（官方一手 / 准官方 / 媒体） | 8 家快讯 + 政府网 + 美联储 + 英文 RSS；有权重，无分级门槛 | 中：缺公告、监管、交易所等一手源 |
| 精选 | 预筛 → 同一标准独立打两次分 → 按信源分级门槛入选；评分按内容类型分轴加权 | 规则打分 + 可选单次 LLM 打分 | 中 |
| 校准 | 金标样本 + 评测脚本 + 后台 SelectBench，逐版对比 | 无 | **大**：没法证明"选得准" |
| 去重 / 聚簇 | 向量召回 + 模型判关系（同一发生 / 后续进展 / 无关 / 汇总），持久化**事件**，事件页有综述和时间线 | 单次运行内 2-gram 去重，不跨期，没有事件概念 | **大** |
| 热度 | 按事件算：48 小时内独立参与方各算一次、24 小时半衰；标"上升 / 新" | 单条新闻打分 | 大 |
| 报告 | 日报（规则编排、不调模型）+ 周报 + 月报（模型只写总述） | 盘前 / 盘后日报 + 周报 | 小 |
| 浏览 | 实时精选流、全部动态、热点榜、主题页（公司 / 方向 / 形态）、搜索、收藏 | 静态日报页、往期、周报、RSS | 大 |
| 机器出口 | 多种 RSS、公开 API、MCP、Agent Markdown、llms.txt | 1 个 RSS | 大 |
| 后台 | 信源管理与试抓、内容诊断、人工改分、模型切换、预算熔断、运行记录、告警 | CLI + 日报页脚的信源状态 | 大 |
| **行情与资金** | 无 | 指数、涨停梯队、板块、主力资金、龙虎榜、沪深港通 | **我们独有** |
| **新闻 × 资金** | 无 | 题材热度 × 板块涨幅 / 资金 / 涨停 → 共振 / 资金先行 / 背离 | **我们独有** |
| **交易日历** | 无 | 经济数据、事件、新股、解禁 | **我们独有** |

结论：**"资讯工程"差距大，但都是 AIHOT 已经解决、可以借鉴甚至直接复用的问题；"市场维度"是我们独有的，要继续加深。**

## 2. 金融场景和 AI 资讯的根本不同

规划时必须考虑这几点，它们决定了不能照搬 AIHOT：

1. **时效决定价值**。AI 新闻晚 2 小时看到无所谓；A 股盘中一条政策快讯，5 分钟后板块就已经反应完。日报是复盘工具，**盘中实时流**才是交易工具。
2. **节奏跟着交易日走**。盘前（07:00–09:15）、盘中（09:30–15:00）、盘后（15:00–18:00 龙虎榜出来）、夜盘 / 海外（20:30 美国数据、22:30 美股开盘）。产品的版次、推送、页面重点要随时段切换。
3. **一切可以被验证**。新闻发出后板块涨没涨、资金进没进，第二天就有答案。可以用历史数据回测"高分新闻 / 共振题材"的后续表现，**把"我们选得准"变成公开可查的数字**。这是对外发布最有说服力的东西。
4. **读者要的是"跟我有什么关系"**。散户关心自己的持仓和自选题材。实体识别（公司 → 股票代码、新闻 → 题材 → 板块）是个性化的基础。
5. **合规是硬约束**。向公众提供个股层面的投资分析、预测、建议，在国内属于需要许可的证券投资咨询业务；实时行情转发需要交易所授权；资讯原文有版权。详见第 8 节，这条决定了公开版能展示什么。

## 3. 产品定位（建议）

### 一句话

> **FinHOT：AI 帮你盯盘前盘后的每一条消息，告诉你哪些事重要、市场认不认、历史上这类信号灵不灵。**

### 目标用户

| 用户 | 场景 | 他们要什么 | 我们给什么 |
|---|---|---|---|
| 上班族散户（主力） | 早上通勤 10 分钟、午休、收盘后 | 不想刷几千条快讯，只要重点和跟自己持仓有关的 | 盘前 / 盘后精选、自选股相关推送、题材雷达 |
| 短线 / 题材交易者 | 盘中盯盘 | 第一时间知道新催化、涨停原因、题材扩散 | 实时精选流、重大消息推送、涨停原因归因、题材热度上升榜 |
| 自媒体 / 投研助理 / 用 AI 做研究的人 | 写复盘、做研究 | 干净、结构化、可引用的数据 | 事件页、周报月报、RSS / API / MCP |

### 和现有产品比

| 产品 | 强项 | 弱点 | FinHOT 的切入点 |
|---|---|---|---|
| 财联社电报 / 金十 | 快、全 | 一天几千条，噪音大；深度功能付费 | 跨源去重 + 精选 + 事件聚合，"只看重要的" |
| 同花顺 / 东方财富资讯 | 行情 + 资讯一体 | 大而全、广告多，资讯与行情没有打通成结论 | 新闻 × 资金交叉验证，直接给出"共振 / 背离" |
| 韭研公社 / 开盘啦这类题材社区 | 涨停原因、题材梳理 | 多靠人工，覆盖和时效受限 | 涨停原因自动归因 + 题材页自动维护 |
| 通用 AI 助手 | 能回答问题 | 没有实时、干净、结构化的 A 股资讯源 | 提供 MCP / API，做 AI 助手的"A 股消息面数据源" |

差异化三件事：**① 精选 + 事件化（借 AIHOT）② 新闻 × 资金验证 + 公开战绩（我们独有）③ 对 AI Agent 友好的出口（借 AIHOT，金融领域稀缺）。**

## 4. 对外站点的信息架构

```
FinHOT
├─ 快讯精选（实时流）   默认首页；按 宏观/政策/海外/行业/公司/市场 筛选；"只看我的自选"
├─ 热点事件            48 小时热度榜，标"上升 / 新"；每个事件一页：综述 + 报道时间线 + 市场反应
├─ 题材雷达            题材热度 × 板块涨幅 × 资金 × 涨停；题材页：定义、新闻时间线、热度曲线、成分股表现
├─ 盘面                今日 / 昨日复盘：指数、涨停梯队 + 涨停原因、板块、资金、龙虎榜
├─ 日历                经济数据、重要事件、新股、解禁、财报披露
├─ 日报 / 周报 / 月报   盘前版、盘后版、周报、月报（报纸版式 + 分享海报）
├─ 我的                自选股 / 自选题材 / 收藏（存在浏览器本地，可导出）
├─ 战绩与方法          信号回测结果、评分标准、信源名单、更新日志（公开透明）
└─ 数据接入            RSS（分栏目）、公开 API、MCP、llms.txt
```

## 5. 功能规划

优先级：**P0** 是对外发布前必须有的，**P1** 是有了明显更好的，**P2** 留作后续。
"借" 表示 AIHOT 已有成熟方案可直接借鉴或复用；"独" 表示我们自己的差异化。

### 5.1 实时化（从"日报"到"实时情报流"）

| 功能 | 说明 | 优先级 | 来源 |
|---|---|---|---|
| 持续采集 | 交易时段每 1–3 分钟拉一次快讯源，其他时段 10–15 分钟；按信源产出自动调频 | P0 | 借 |
| 实时精选流 | 新闻到站后几分钟内完成去重、打分，够格就上首页；首发时间 → 上站时间可度量 | P0 | 借 |
| 重大消息推送 | 飞书 / 企业微信 / Telegram / 邮件；按"重大级别 + 自选题材 / 自选股"过滤，单日推送上限防打扰 | P1 | 借 + 独 |
| 时段化版次 | 盘前要点（08:30）、午间（11:40）、盘后复盘（16:00）、夜盘关注（20:00），各自重点不同 | P1 | 独 |

### 5.2 事件化（AIHOT 的核心，我们最大的短板）

| 功能 | 说明 | 优先级 | 来源 |
|---|---|---|---|
| 持久化事件 | 新闻存库；跨天聚成事件，区分"同一发生 / 后续进展 / 无关 / 汇总稿"；人工改过的归属不被覆盖 | P0 | 借 |
| 热点事件榜 | 48 小时窗口，独立来源各算一次，24 小时半衰；与 6 小时前比较标"上升 / 新" | P0 | 借 |
| 事件页 | 综述（模型写，只用报道里的事实）+ 报道时间线 + 相关题材 / 个股 + **事件发生后的板块走势** | P1 | 借 + 独 |
| 社交热度信号 | 东财 / 同花顺人气榜、雪球 / 股吧热帖作为"讨论热度"计入事件热度（类似 AIHOT 把 X 讨论算进热度） | P2 | 借 + 独 |

### 5.3 题材与个股（A 股差异化的地基）

| 功能 | 说明 | 优先级 | 来源 |
|---|---|---|---|
| 实体库 | 公司名 / 简称 / 曾用名 → A、H、美股代码；题材词典 → 东财 / 同花顺概念板块代码；定期从行情接口同步 | P0 | 独 |
| 题材页 | 题材定义、近 30 天新闻时间线、热度曲线、板块涨幅与资金、成分股涨停、相关事件 | P0 | 借（主题页）+ 独 |
| 涨停原因归因 | 每只涨停股匹配当日相关新闻 / 公告 / 题材，写一句"涨停原因"，按题材聚类成"涨停梯队 + 原因"表 | **P0** | 独（散户最高频的需求之一） |
| 题材热度上升榜 | 新闻热度、讨论热度、板块资金三条曲线，标"新出现 / 加速 / 退潮" | P1 | 独 |
| 个股页 | 公司新闻、公告、互动问答、龙虎榜、所属题材 | P2 | 独 |
| 自选股 / 自选题材 | 浏览器本地保存；首页"只看我的"；周报给出"你的自选本周发生了什么" | P1 | 借（收藏）+ 独 |

### 5.4 信源扩充与分级

| 信源 | 价值 | 优先级 |
|---|---|---|
| 巨潮资讯上市公司公告（重大事项、业绩预告、回购增持、问询函） | 个股一手源，涨停归因必需 | P0 |
| 证监会 / 交易所 / 央行 / 统计局 / 发改委官网 | 政策一手源（目前靠快讯转载） | P1 |
| 互动易 / 上证 e 互动 | 题材炒作的重要催化来源 | P1 |
| 券商研报标题与摘要（东财研报中心等） | 机构观点与行业逻辑 | P2 |
| 雪球 / 股吧 / 微信公众号（财经大号） | 讨论热度、观点 | P2 |

同时引入 AIHOT 的**三级信源**：T1 官方一手（公告、监管、统计局）、T1.5 准官方（官方媒体账号、交易所平台）、T2 媒体与个人。不同级别用不同入选门槛。

### 5.5 精选质量与可信度

| 功能 | 说明 | 优先级 | 来源 |
|---|---|---|---|
| 金融版评分标准 | 借 AIHOT"按内容类型分轴加权"：类型（政策 / 宏观数据 / 产业 / 公司公告 / 海外 / 市场行情）× 轴（市场影响面、信息增量、证据强度、时效性、可交易性）；规则分做预筛省钱 | P0 | 借 |

| **信号回测** | 历史数据回测：高分新闻、共振题材在 T+1 / T+3 / T+5 的板块超额收益与胜率 | **P0** | 独 |
| **公开战绩页** | 按月公布信号表现（含失败的），以及方法说明 | P1 | 独（对外发布的信任基础） |

## 6. 技术路线（需要拍板）

现有 Python 批处理 + 静态站，撑不起"实时 + 事件 + 搜索 + API"。三条路：

| | A. 继续演进 Python | B. 整体迁到 AIHOT 框架 | C. 混合（推荐方向，先验证） |
|---|---|---|---|
| 做法 | 加 SQLite/Postgres + 常驻调度 + FastAPI 网站，事件 / 热度 / 搜索 / API / MCP 自己写 | Fork AIHOT（Node + TypeScript + Postgres），A 股功能全部用 TS 重写成模块 | AIHOT 引擎负责资讯（精选、事件、热度、网站、RSS / API / MCP、后台）；FinHOT Python 变成 **A 股数据服务**：快讯采集后经 AIHOT 的"外部推送"接口送入，行情 / 涨停 / 资金 / 日历 / 回测由 Python 产出，AIHOT 模块展示 |
| 优点 | 技术栈不变，你和本地 AI 都熟 | 一套代码，体验最完整 | 资讯工程直接用成熟方案；A 股数据继续用 Python 生态（akshare / pandas 做回测很方便） |
| 缺点 | 要重造 AIHOT 已有的大量轮子，周期长、质量难追平 | A 股数据与回测在 TS 里写很别扭；改动量最大 | 两个服务、两种语言；需要服务器；跟随上游更新有合并成本 |
| 估计周期（含 AI 辅助） | 6–10 周到可公开 | 6–8 周 | 4–6 周 |

**建议：先花约 1 周做验证，再决定。**

1. 本地按 AIHOT 文档起一个站，把分类、信源、提示词改成财经版；
2. 写一个推送脚本，把 FinHOT 每轮采集、去重后得分靠前的快讯推进去（只推前一部分，控制模型成本）；
3. 跑 3 个交易日，看三件事：精选质量、事件聚合效果、模型花费。

满意就走 C；不满意（比如成本太高、不好改）就走 A，把 AIHOT 的算法（热度公式、事件关系定义、报告编排规则）移植到 Python。

**无论走哪条路都要做的 Python 侧工作**（第 9 节阶段 1）：实体库、公告源、涨停原因归因、回测、社交热度。这些是 A 股专属能力，两条路线都用得上，不会白做。

## 7. 部署与成本（粗估）

| 项 | 方案 | 月成本（估） |
|---|---|---|
| 服务器 | 2 核 4G。香港 / 新加坡云（免备案，访问国内接口一般没问题）或国内云（需 ICP 备案，访问最快） | 50–150 元 |
| 数据库 | 同机 Postgres（C 路线）/ SQLite（A 路线） | 0 |
| LLM | 规则预筛后每天 400–800 条进模型，每条约 3–5 次调用。用 GLM-flash / DeepSeek 一类便宜模型 | 约 30–300 元，强依赖模型与条数，需实测 |
| 域名 + CDN | — | 约 10–30 元 |
| 推送 | 飞书 / 企业微信 / Telegram 免费；短信、邮件按量 | 0–少量 |

GitHub Actions + Pages 免费方案可以继续当**备用 / 个人版**，但满足不了实时需求，而且 GitHub Pages 在国内访问不稳定。

## 8. 合规与风险（对外发布前必须想清楚）

> 以下是基于公开信息的一般性理解，不是法律意见。正式对外（尤其涉及收费、推广）前，建议咨询熟悉证券业务的律师。

| 风险 | 说明 | 建议做法 |
|---|---|---|
| **证券投资咨询** | 向公众提供具体证券的投资分析、预测或建议，属于需要证监会许可的证券投资咨询业务；"荐股"更是重点监管对象 | 公开版定位为"资讯聚合与整理"：保留事实、题材 / 板块关联、历史统计；**去掉对个股的"利好 / 利空"判断和"或活跃 / 或承压"这类预测性表述**；个人版可保留。全站免责声明 |
| 行情数据授权 | 交易所实时行情的再分发需要授权；收盘后的统计数据风险较低 | 公开站点只展示收盘后数据或统计口径（涨停数、板块收盘涨幅），不做实时行情；正式商用考虑正规数据源（交易所授权商、Tushare Pro 等） |
| 资讯版权 | 财联社等原文有版权，多数禁止转载 | 只展示标题、**自己写的摘要**和原文链接，不展示全文；提供下架通道并快速响应 |
| 非官方接口 | 东财、新浪、财联社的网页接口没有授权，可能随时改版或封禁；商业使用风险更高 | 采集层继续保持单源隔离 + 健康监控；商业化前替换关键数据源 |
| 网站备案 | 国内服务器对外提供网站需要 ICP 备案；经营性服务另有许可 | 起步用香港服务器，或个人备案 + 非经营性 |
| 模型幻觉 | 写错公司、编数字会误导交易 | 已有"个股必须在原文出现"的校验；扩展到数字核对；事件综述只用报道中的事实（AIHOT 做法） |

## 9. 分阶段路线图

### 阶段 0：决策与验证（约 1 周）

- 拍板第 10 节的问题；
- AIHOT 财经版本地验证（见第 6 节）；
- 标注第一批 200 条金标样本（你来标，我来写工具），作为后续所有提示词改动的基准。

**验收**：选定技术路线；有一份"3 个交易日精选质量 + 花费"的对比记录。

### 阶段 1：A 股数据底座（约 2–3 周，路线无关）

- 实体库：A / H / 美股公司名与代码、题材 → 概念板块映射，每日同步；
- 新信源：巨潮公告（P0）、官方网站（P1）；
- **涨停原因归因 v1**：涨停股 × 当日新闻 / 公告 / 题材，规则匹配 + 模型写原因；
- **回测 v1**：用 `data/` 已积累的数据 + 历史行情，算"高分新闻 / 共振题材"的 T+1 / T+3 / T+5 表现；
- 金融版评分标准 + 评测脚本，用阶段 0 的金标样本校准。

**验收**：涨停股有原因的比例 ≥ 80%；回测报告能按题材、按信号类型给出胜率与超额；评分在金标集上的查准率有基线数字。

### 阶段 2：实时站内测（约 3–4 周）

- 部署服务器，持续采集，实时精选流；
- 事件聚合与热点事件榜、事件页；
- 题材雷达与题材页、盘面页（涨停梯队 + 原因）、日历页；
- 日报 / 周报 / 月报迁到新站，旧的静态站保留为备份；
- 搜索、分栏目 RSS、飞书或 Telegram 推送；
- 后台最小版：信源健康、运行记录、预算熔断。

**验收**：盘中重大消息从首发到上站 P50 ≤ 5 分钟；连续 10 个交易日无人工干预稳定运行；邀请 10–20 位朋友内测并收集反馈。

### 阶段 3：差异化与可信度（约 2–3 周）

- 新闻 × 资金 2.0：盘中滚动更新；事件页附"事件发生后的板块走势"；
- 公开战绩页（按月更新，含失败案例）；
- 自选股 / 自选题材与个性化推送；
- MCP 服务、公开 API、llms.txt；分享海报。

**验收**：战绩页上线；MCP 能被 Claude Desktop / Cursor 等接入并查到当天数据；内测用户周留存有基线数字。

### 阶段 4：公开发布与运营（持续）

- 合规复核（第 8 节）、免责声明、下架通道、隐私说明；
- 域名、备案或香港部署、SEO；
- 运营指标：日活、订阅数、推送打开率、战绩；
- 可选的长期方向：高级推送、API 配额、团队版。是否收费取决于合规结论，现阶段不建议。
