# FinHOT 个性化：从“同一份报告给所有人”到“与我有关”

> 写于 2026-10-16。这一轮主攻“与我有关”，把“可验证”延伸到个人维度。通用日报、周报、静态站、网站、回测照常运行，
> 个性化是叠加在上面的一层，只在本机或服务器上生成，通过私人渠道送达。

## 一、现状核对（用 10/13–10/14 的数据重算）

| 原来的说法 | 实测 | 补充 |
|---|---|---|
| 10/14 盘前版必读 10 条里 8 条是中东或美联储 | 属实（8/10） | 这 8 条其实只是两三件事：去重只合并“同一条消息”，同一件事的不同进展各占一条。这是冗余，不只是“偏宏观” |
| 10/13 盘后 67 只涨停只有 6 只“高” | 属实（10/14 盘前版 5/67） | “高”= 同花顺原因 + 标题被正则命中“催化”词，有误判：威派格“上半年营收…净亏损…”因含“营收”被判高。67 只里大量是冰雪、PCB、染料题材跟涨，本来就没有公司公告，“高”的比例有天花板 |
| 利好利空自相矛盾；规则分类误判 | 属实 | 根因一：`analyze.md` 每条只有一个 direction 却对应最多 3 个板块，第 2 条把美联储鹰派和中东混在一条里整体判了利空。根因二：两条误判都没进模型，`^XX：` 规则把“黎巴嫩总统重申：”当成公司。实测 10/10–10/14 被归为“公司”的 491 条里约 80 条是官员、机构、券商观点 |
| 主题页 17 家公司、35 个题材；前 80 条进模型 | 属实 | 上限 80，实际每期成功 57–66 条；10/01–10/08 全是规则版。`data/` 每期只存前 400 条（去重后约 750 条） |
| 回测：精选利好反应 +0.30%（62%）、可交易 +0.11%（46%）；共振反应 +0.31%、可交易 0.00% | 一致 | 数据从 9/30 才开始，有模型方向的只有 10/09 起约 5 天；回测是题材层面（板块中位数），不是个股 |
| “中信证券”这类名字的新闻 | — | 10/10–10/14 提到中信证券的 15 条里 10 条是“中信证券：看好……”的研报观点，其余是保荐人、承销商名单，没有一条在说它自己。实体链接必须判“角色”，只认名字不够 |

结论不变：价值不在更多新闻，而在“与我有关”。但个性化解决不了回测揭示的“等能买时已经反应完”——它的价值是省时间、不漏持仓大事，
所以评估指标看“相关占比 / 不相关率 / 持仓重要公告漏报”，不看收益命中率。

## 二、设计

### 0. 隐私：画像和个人数据绝不进公开仓库

仓库是公开的，GitHub Actions 会自动提交 `reports/`、`data/`，公开仓库的 Actions 日志也是公开的。所以：

- 画像在 `FINHOT_PROFILES_DIR`（默认仓库下的 `profiles/`，`.gitignore` 里只放行 `profiles/example.yaml`）；
- 个人数据（简报、候选、推送记录、反馈）在 `FINHOT_PRIVATE_DIR`（默认 `.private/`；服务器上是推送进程数据卷的 `private/`）；
- 这两个目录配到 `reports/`、`data/`（`data/private`、`data/profiles` 除外，已 gitignore）、`_site/`、`sources/`、`docs/`、`web/` 下面会直接报错；
- `GITHUB_ACTIONS=true` 时拒绝读画像、拒绝生成个人内容；
- **关系库是个人数据**：只为自选股生成的关系表一旦入库就等于公开了持仓，所以关系放在画像里，不放 `sources/`；
- 公开数据（全 A 股清单、全市场按类型过滤的公告、按公告类型的事件研究）不含任何人的自选，可以入库。

### 1. 画像（`finhot/profile.py`，示例 `profiles/example.yaml`）

```yaml
name: 我
holdings: ["300750"]          # 持仓（代码）
watch: ["002594", "688981"]   # 自选观察
themes: [锂电储能, 算力, 半导体] # 名字和 finhot/themes.py 一致；冷启动只选 3 个题材也能出简报
style: 波段                    # 短线 / 波段 / 中长线
hours: ["08:20", "15:45"]     # 常看时段：到点出简报（12 点前盘前版，15 点后盘后版）
push: {channel: feishu, webhook: ..., secret: ..., daily_limit: 8, quiet: "22:30-07:30"}
aliases: {"002594": [比亚迪股份]}
relations:                     # 个人关系库（只走一层）
  - {code: "300750", target: "002460", kind: 上游, source: 人工维护, confidence: 1.0, status: 已确认}
```

- 导入：`profile import 我 文件 --as holdings|watch`。同花顺 / 东方财富导出的 CSV、TXT（UTF-8 或 GBK）、随手粘贴的清单都行：
  先认代码（`SZ300750`、`600519.SH`、`（300750）`），没代码的行按简称对，对不上的列出来；
- 多份画像：`profiles/` 下一人一个文件，各用自己的私人群。

### 3. 实体链接（`finhot/linker.py`）

- 代码只认带括号或交易所前后缀的写法，裸六位数多半是金额；名字按**最长匹配**（“中信建投”不会被当成“中信…”）；
  现名、去 ST 的简称、别称、曾用名都认；一个名字对应几家（曾用名和现名撞了）时现名优先，否则不认；
- 本身是常用词的简称（机器人、太阳能、农产品……，`aliases.yaml` 的 `generic`）只有带代码、“简称：”开头，
  或后面紧跟“股份 / 公司 / 涨停 / 股价 / 公告”时才算；
- **角色**（这是“与我有关”的关键）：

  | 角色 | 判法 | 默认权重 |
  |---|---|---:|
  | 主体 | 标题“公司名：”开头；或标题点到它、又不是别家观点的对象、不是行情播报 | 1.0 |
  | 标题点名 | 标题里出现但不是主语（“长江证券：维持蓝思科技买入评级”里的蓝思科技；“XX 板块拉升 YY 涨停”） | 0.8 |
  | 信源关联 | 只在正文出现，财联社等信源也标成了关联个股 | 0.5 |
  | 正文提及 | 只在正文出现 | 0.3 |
  | 行情名单 | 收评、异动里一串名字中的一个 | 0.25 |
  | 观点来源 | 券商 / 机构观点的发布方（“中信证券：金价底部或抬升”），说它自己经营的除外 | 0.1 |
  | 中介 | 保荐人、承销商、托管人、财务顾问 | 0.1 |

- 实测（最近 7 天 4400 条快讯，`python -m finhot entities link`，我自己逐条核对，不是独立标注，数字只作参考）：
  - 种子清单阶段核对了约 150 次点名，修了 4 类角色错误（别家券商评级的对象、“A股收盘：…贵州茅台…”、标题里列了几家公司、券商标题默认当观点）；
  - **换成全市场清单后第一次抽 60 次点名，约 25 次是错的**：*ST 股去掉前缀后的两字简称（“*ST发展”→“发展”、“*ST动力”→“动力”、“ST标准”→“标准”）
    和常用词、地名简称（太平洋、驱动力、金融街）到处误命中。改成：*ST 去前缀后不到 4 个字的不认，两个字的简称和 `generic` 里的常用词 / 地名
    必须带公司语境；又修了“券商：…利润有望…”和“机器人公司”两处；
  - 修完换一个随机种子重新抽 50 次点名：50 次的公司都对，角色有 1 次可以商量（“长鑫科技市值跌破3万亿元，工商银行重回总市值第一”里工商银行算主体）。
    按里程碑的口径（≥90%）通过，但样本小、是我自己判的，建议你用 `entities link --sample 50 --seed <任意数>` 再抽一次。

同一套规则也修了通用日报的“公司”分类：`XX：` 打头只有 XX 是上市公司（或不像官员、机构、券商观点）时才算公司新闻。

### 4. 个股一手信源：公告（`finhot/fetchers/notices.py`、`finhot/announce.py`）

- 巨潮（P0，证监会指定披露平台）和东方财富公告中心（备用）各一个 `@register` 适配器，配置在 `sources.yaml` 的 `announcements`
  （不进快讯流），单源隔离，`python -m finhot sources` 末尾检查它们（按沪深京分别计数，看栏目是否覆盖全）；两边结果按
  （代码, 标题）去重合并；
- 公告类型表 `sources/announcements.yaml`：18 类（业绩预告、停复牌、退市与 ST、监管问询、控制权变更、重组并购、澄清与异动、
  增持、减持、回购、解禁、重大合同、股东变动、定期报告、分红送转、融资、股东大会、经营动态），每类有通用重要性、
  是否即时提醒、是否算涨停“催化 / 提示”、是否进白名单；摘要、英文版直接跳过；
- **过滤先于模型**：公告不进模型，标题已经说清楚是什么事；
- 用在哪：
  - GitHub Actions 的日报：取全市场、按类型白名单过滤，存 `data/<日期>/announcements*.jsonl`（公开数据），给涨停归因、事件研究；
  - 服务器盘面任务：按当天涨停股的代码查前两天的公告（比全市场翻页省）；
  - 个人简报和提醒：按持仓、自选、确认过的关联公司的代码查；
- 涨停归因：公告按**代码**对上（比按名字找新闻可靠），类型是催化且标题不是坏消息（“预亏”“下滑”）的，可信度为“高”；
  澄清、异常波动类当“提示”。同时修了“营收 / 净利润”误当催化的问题（10/13 盘后重算：高 6 → 5，去掉了威派格）；
- 互动易 / 上证 e 互动（P1）这一轮没接：没有可在这里验证的稳定接口，留到下一轮（见“遗留”）。

### 5. 个人排序（`finhot/personal.py`，权重在 `sources/personal.yaml`）

```
排序分 = 通用重要性 × 关联强度 × 点名方式 × 新鲜度 × 反馈修正
```

| 因子 | 默认 |
|---|---|
| 通用重要性 | 公告：类型表的 importance；快讯：日报同一套分数（规则分，配了模型是融合分）；网站精选过的取 max(规则分, 网站评分/10) |
| 关联强度 | 持仓 1.0 · 自选 0.8 · 关联公司 0.55（关系库确认过的，一层）· 关注题材 0.45 · 同行业 0.35 · 宏观 0.2 |
| 点名方式 | 见上面角色表 |
| 新鲜度 | 12 小时内 1.0 · 24 小时内 0.8 · 72 小时内 0.5 · 更早 0.3；同一件事 3 天内给过就不再给（同一条、或标题字面很像；公告除外，公告本身就是新进展） |
| 反馈修正 | 每类理由（如“持仓·主体”“关注题材”）有 ≥5 条反馈后，按有用 / 不相关的比例在 0.5~1.5 之间调 |

不按一个总分混排，而是**分栏**（持仓 / 自选 / 关联公司 / 关注题材 / 宏观），栏内按排序分，排序分低于 2.5 的不要；
持仓、自选里只是顺带提到的（正文提及、行情名单、机构观点、中介）不单列，每栏末尾合成一行“另有 N 条只是顺带提到”。
这样互动问答、小公告这类“通用分低但和你直接相关”的不会被宏观大事压下去，宏观照常保留但压成一段。

**为什么给你**只引用事实：`持仓 比亚迪 · 新闻主体`、`持仓 宁德时代 · 公告（业绩预告）`、
`持仓 宁德时代 的上游 · 赣锋锂业新闻主体 · 关系来源：人工维护`、`关注题材 锂电储能`、`自选 中芯国际 同行业（半导体）· …`。
不写利好利空、不写预测；网站精选的“A股影响”改写成“可能影响：半导体、存储”。

### 6. 产出

1. **我的盘前 5 分钟 / 盘后简报**（`finhot/brief.py`，`python -m finhot brief --profile 我`）：
   持仓相关 → 自选观察 → 关联公司 → 关注题材（每个题材一行“新闻 N 条 · 板块 ±x% · 主力 ±y 亿 · 涨停 z 家 → 共振 / 资金先行 /
   新闻热·资金冷”，下面几条新闻）→ 日程（持仓、自选未来 7 天的解禁、业绩预约披露）→ 宏观一段（按主线压缩，
   主线在 `sources/stories.yaml`）→ 免责声明。时间窗口接着上一份简报（6~72 小时）。
   不配模型也能出：快讯规则分 + 公告类型表；配了网站时读网站精选（模型在网站那边已经算过，这里不再调模型，也不和网站抢 GLM 并发）；
2. **即时提醒**（`finhot/alerts.py`，在服务器常驻的 `push.py` 里每轮跑）：到点出简报并发送；持仓 / 自选的公告（类型表 push 为 true 的）
   每 5 分钟按代码查一次；持仓 / 自选成为新闻主体、排序分 ≥ 5 的快讯；持仓股盘中涨跌超过 5%（每只每天每个方向一次）。
   飞书 / 企业微信群机器人 webhook；每人每天上限（默认 8），免打扰时段里的记成“延后”、由下一份简报带上；同一条只推一次。
   **没做“新闻热·资金冷 → 共振”的即时提醒**：回测里共振可交易口径 T+1 是 0.00%，没有证据值得为它打扰人；
   服务器上也拿不到东方财富板块资金（只有新浪涨幅），盘中判定会来回跳。它照常出现在简报的“关注题材”里；
3. **我的周报**（`brief --weekly`）：你的自选本周发生了什么（给过你的条目按股票归拢）+ 关注题材的信号战绩（从公开回测里挑你的题材）
   + 本周你收到的公告类型在全市场的历史表现；
4. **后续（只给方案，暂不实现）**：见第五节。

### 7. 闭环

- **反馈**：消息和简报里每条后面是“有用 · 不相关 · 已知道”的签名链接（群机器人是单向的，收不到按钮点击），点开由推送进程里的
  小服务记一条（`finhot/feedback_server.py`，`FINHOT_FEEDBACK_SECRET` 签名防伪造，链接里没有持仓）；没开端口时用
  `python -m finhot feedback add`。反馈存在个人数据目录，用来调各类理由的权重（见上）；
- **评估**（`finhot/evaluate.py`）：
  - `eval --profile 我`：给了多少、推了多少、延后 / 超上限多少；相关占比、不相关率，按栏目、理由类别、渠道分开；反馈带来的权重修正；
    推送打开率拿不到（群机器人没有已读回执），只统计点了反馈链接的；
  - `eval --profile 我 --pool`：**盲标对比**。直接比“我标为有用的条目”有选择偏差（你只看得到个性化排出来的），所以把每份简报里
    个性化和通用排序各自的前 10 条合并、打乱，生成标注页（看不出来自哪种排序），标完 `--labels` 导入，算两种排序的 precision@10；
  - `backtest --announcements`：**按公告类型的事件研究**（全市场同类公告之后个股相对中证 1000 的超额，反应 / 可交易两种口径，T+1/T+3）。
    一个人几十只股票、几周时间按“关联强度”分的回测样本只有个位数，没有统计意义；全市场按类型做，样本大得多，
    结果是公开统计，个人周报里引用。原有回测（题材 × 信号类型）不变，按题材、信号类型分开的表已经有了。

和现有部分的接口：

- `docker-compose.yml`：推送进程挂载 `./profiles`、只读挂载 `./data`（关系归纳、我的周报读公开数据），映射 8790 端口（没设密钥时没有服务在听）；
- 通用日报：`analyze.md` 改成每个板块各自给方向（`impacts`，旧数据照常读），回测按每个板块自己的方向出信号；
  必读里同一件事（同一主线 / 主题材 / 标题字面很像）最多 2 条（10/14：8 条中东美联储 → 4 条，10 条覆盖 8 件事）；

## 五、后续方案（暂不实现）

**事件订阅**（“美伊局势”“出口退税”，有新进展才提醒）：画像加 `subscriptions: [{name, keywords, min_score}]`；
推送进程每轮对新快讯按关键词 + 聚簇匹配，同一订阅已提醒过的事件只有在“和之前提醒过的都不像”（新进展）时再提醒，
复用 `history.py` 的账本和 `personal.similar`；网站侧可以改用引擎的事件（`/api/v1` 里事件的更新时间）判断有没有新进展。
宏观主线（`sources/stories.yaml`）就是订阅的公共版本。

**网站“只看我的”**：引擎的设计是“公开内容匿名，管理员和访客看到的一样”，收藏存在浏览器本地（`apps/web/app/lib/local-state.ts`）。
做法：自选存在浏览器本地（和收藏同样的方式，可导入导出），精选条目带上 FinHOT 推送时识别出的代码（`raw.finhot.codes`，
推送进程用 `linker.py` 补上），前端按本地自选过滤。要动 `apps/web` 的列表组件和推送接口的 `raw` 字段，属于引擎改动，
要记进 `ENGINE.md`；引擎的公司主题（`ENTITIES`）不能扩到 5000 家（模型打标签的词表会爆），所以走代码过滤而不是主题。

## 六、遗留问题

- 两个公告接口和全市场股票清单已在 GitHub Actions 上实测；东财预约披露和个股行情接口还没实测，
  格式按公开资料实现、用离线样例测；服务器上第一次跑时看 `python -m finhot sources` 和日志；
- 巨潮公告的时间只到日期：没有东财同一条的精确时间时，按当天 0 点算新鲜度（盘后发的公告第二天早上会被打 0.8 折左右）；
- 巨潮全市场翻页一天约 100 页，GitHub Actions（海外）上可能被限或连不上，那时只有东财备用源；
- 互动易 / 上证 e 互动没接；
- 关系归纳只认模板句，召回不高；同行业只按东财行业，粒度粗（“半导体”“电池”很宽），简报里“关联公司”栏会出现同行业的大新闻，
  觉得吵就调低 `sources/personal.yaml` 的 `relevance.同行业`，或让反馈把它压下去；
- 盲标和反馈修正都依赖你标注；样本少时修正系数会被钳在 0.5~1.5 之间，不会大起大落；
- 推送进程常驻在 4 核 4G 上：个人一轮主要是几个 HTTP 请求和规则计算，画像少时开销可以忽略；每 5 分钟按代码查公告，
  画像里股票很多（上百只）时巨潮按公司查会变慢，可以改成东财按代码批量查。
