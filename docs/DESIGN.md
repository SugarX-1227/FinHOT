# FinHOT 详细设计

本文档是给开发 Agent（云端 AI）的施工说明书。请按阶段实现，每个阶段结束时项目应可运行、可验证。

> **实现现状（v0.1）与本文的差异**
> - 信源配置改为 `sources/sources.yaml`（YAML 可写中文注释），字段见文件头部说明。
> - 采集不依赖多次定时抓取：每个快讯源按时间窗口自动翻页（24 小时内一次拿全）；单源失败只记录不中断。
> - LLM 流水线合并为一次批量调用（分类+打分+摘要+A股映射），另有一次"盘前要点"总结；
>   未配置 `LLM_API_KEY` 时整条流水线退化为规则版（`finhot/scoring.py`），日报照常生成。
> - 已实现 M1~M4；证券时报接口无翻页，仅取最新约 30 条；央行/证监会官网未直接接入（快讯源均第一时间转载）。

## 1. 总体流程

```
信源配置(sources/) → 采集器 → 去重 → LLM 流水线(分类→打分→摘要→A股映射) → 日报渲染 → commit 到 reports/
                                                              ↑
                                              由 GitHub Actions 每日盘前定时触发
```

核心原则（借鉴 AIHOT，做了减法）：

1. **信源与代码分离**：信源全部放配置文件，加源不改代码。
2. **提示词与代码分离**：所有 LLM 提示词放 `prompts/` 目录，调标准不改代码。
3. **预算熔断**：每日进入 LLM 的条目数和 token 数设硬上限，防止费用失控。
4. **防幻觉**：摘要和标题只允许使用原文信息，A股映射的板块/个股结论必须标注推断依据；禁止编造原文未提及的公司。

## 2. 信源清单（第一期）

| 信源 | 类型 | 说明 | 优先级 |
|---|---|---|---|
| 财联社电报 | 网页/接口 | A股快讯时效性最好，主打 | P0 |
| 华尔街见闻 | 网页/RSS | 宏观快讯 | P0 |
| 金十数据 | 网页 | 宏观数据、海外市场 | P1 |
| 东方财富/新浪财经 | RSS | 综合财经 | P1 |
| 央行/证监会/财政部/发改委/统计局 | 网页公告 | 政策一手信源 | P1 |
| 海外隔夜行情（美股指数、美债、美元、离岸人民币、原油黄金） | 接口 | 盘前必看，可用 akshare 或免费行情接口 | P0 |
| Reuters/Bloomberg/CNBC | RSS | 海外宏观，可选英文源 | P2 |

配置格式（`sources/sources.json`）：

```json
{
  "id": "cls-telegraph",
  "name": "财联社电报",
  "type": "api | rss | html",
  "url": "...",
  "tier": "official | media",
  "priority": "P0",
  "interval_minutes": 30,
  "enabled": true
}
```

> 注意：财联社等站点反爬与接口变动频繁，采集器要做成可失败的单源隔离——某个源挂了记日志跳过，不影响整条流水线。

## 3. LLM 流水线

模型：任意 OpenAI 兼容 API（环境变量 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 可配）。

| 步骤 | 输入 | 输出 | 说明 |
|---|---|---|---|
| 预筛 | 单条原文 | 保留/丢弃 | 纯文本分类，便宜模型即可 |
| 分类打分 | 单条原文 | 类别 + 0-10 分 | 类别：宏观/政策/行业/公司/海外/资金面；打分标准写进提示词 |
| 摘要 | 原文 | 中文标题+摘要 | 只用原文信息 |
| A股映射 | 摘要 | 方向 + 板块 + 标的 | 本项目核心增量，见下 |

A股映射输出结构：

```json
{
  "direction": "利好 | 利空 | 中性",
  "sectors": ["固态电池", "锂矿"],
  "etfs": ["电池ETF"],
  "stocks": ["宁德时代"],
  "horizon": "短线情绪 | 中期逻辑",
  "confidence": 0.7,
  "basis": "映射依据（引用原文中的事实）"
}
```

打分与映射结果落盘为 `data/YYYY-MM-DD/items.jsonl`，方便回测"高分新闻次日板块表现"，持续校准提示词。

## 4. 日报格式（`reports/YYYY-MM-DD.md`）

```markdown
# 财经热点日报 · 2026-09-30（盘前版）

## 一、隔夜海外市场
美股三大指数 / 美债收益率 / 美元指数 / 离岸人民币 / 原油黄金（表格）

## 二、宏观与政策
（按重要性排序，每条：标题 + 2-3 句摘要 + 影响标注）

## 三、行业与产业动态
（按 A 股板块归类；每条标注 利好/利空 + 相关板块/ETF）

## 四、公司公告与个股大事

## 五、今日关注
（经济数据日历、新股申购、限售解禁、重要会议）

---
*生成时间 / 信源状态 / 条目数 / LLM 用量。内容仅为信息整理，不构成投资建议。*
```

## 5. 调度

GitHub Actions（`.github/workflows/daily.yml`）：

- 盘前版：北京时间 07:30（cron 用 UTC：`30 23 * * *`，前一日 23:30 UTC）
- 盘后版（可选）：北京时间 16:00
- `LLM_API_KEY` 放 repo Secrets；产物直接 commit 回 `reports/`
- 注意 cron 排队抖动，脚本内部不要依赖精确触发时间

## 6. 给开发 Agent 的实施顺序

1. **M1**：项目骨架 + `sources.json` + 采集器（先跑通 RSS 类源），输出 `data/raw/` JSON。验收：手动运行能拿到 ≥20 条真实条目。
2. **M2**：去重（规范化 URL + 标题 simhash/编辑距离）。验收：同事件多源只留一条。
3. **M3**：LLM 流水线 + 提示词文件化 + 预算熔断。验收：对单日条目跑完全流程，产出 items.jsonl。
4. **M4**：日报渲染 + Actions 定时 + 自动 commit。验收：连续 3 天自动产出日报。
5. **M5+**：周报、热度榜、akshare 接入涨停池/龙虎榜/北向资金做"新闻 × 资金"交叉验证。

## 7. 风险与合规

- 版权：只存标题+摘要+原文链接，不做全文转载；日报加免责声明。
- 反爬：控制频率、带 UA、失败退避；接口随站点变动需要维护成本，采集层必须模块化。
- 时效：A 股盘前信息价值最高，流程要在 07:30 前完成，LLM 步骤控制在预算内保证速度。
